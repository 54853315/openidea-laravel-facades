# Laravel Facades for OpenIDEA

Laravel registers its facades (`Route`, `Auth`, `DB`, `Cache`, …) at runtime with
`Illuminate\Foundation\AliasLoader`, which calls `class_alias()`. A file in the global
namespace may therefore use the short names without a `use` statement — that is what
`routes/api.php` files do:

```php
<?php

Route::middleware('feature:card_issuing')->group(function () {
    Route::get('card-products', [CardProductController::class, 'index']);
});
```

OpenIDEA's PHP language server (Intelephense) does not run the application, so it sees
`Route` as an undefined type and reports **`Undefined type 'Route'`** (`P1009`). In VS Code
and PhpStorm this is solved by the conventional generated `_ide_helper.php`, which
declares the aliases for the IDE. Intelephense understands `class_alias()`, so a small
file with one call per alias is enough.

This plugin generates that file for a Laravel project:

```php
class_alias(\Illuminate\Support\Facades\Route::class, 'Route');
class_alias(\Illuminate\Database\Eloquent\Model::class, 'Eloquent');
// …
```

The aliases are read from the installed framework
(`vendor/laravel/framework/src/Illuminate/Support/Facades/Facade.php`), so they follow the
project's Laravel version instead of a hard-coded list. Aliases from `config/app.php` are
added when that file has a literal `aliases` array.

## Install

- **From a package:** Settings › Plugins › _Install Plugin from Disk…_ and pick this
  folder (or a `.oiplugin`).
- **Project plugin:** copy/symlink the folder to `<project>/.openidea/plugins/laravel-facades/`.
  It loads in trusted projects after you approve its capabilities.

The first PHP file you open in a Laravel project creates `_ide_helper.php` in the project
root. Intelephense indexes it and the `P1009` warning for `Route` (and the other facades)
disappears. If the file already exists and was not generated by this plugin — for example
by `barryvdh/laravel-ide-helper` — it is left untouched.

The command **Laravel: Generate Facade Stubs** regenerates the file by hand, for example
after `composer update` adds a facade.

## Capabilities

| Capability | Why |
| --- | --- |
| `project.read` | Read `composer.json`, the framework's `Facade.php`, `config/app.php`, and the existing `_ide_helper.php`, and find the project root. |
| `events` | React to a PHP file being opened and to `composer.json` / `composer.lock` being saved. |
| `process:tee` *(optional)* | Write `_ide_helper.php` on macOS and Linux. |
| `process:php` *(optional)* | Write `_ide_helper.php` on Windows and where `tee` is not installed. |

The plugin never runs arbitrary commands: `tee` receives the generated text on stdin, and
`php -r` only calls `file_put_contents($argv[1], stream_get_contents(STDIN))` with the
relative path of the generated file. Refuse both process capabilities and the plugin still
loads; it tells you what to grant when it first needs to write, and you can run the command
after granting.

## Limitations

- Only names in the **global namespace** are covered, which is where Laravel's route files
  live. A namespaced file still needs `use Illuminate\Support\Facades\Route;`; there the
  short name means `App\…\Route`, not the alias.
- Aliases registered at runtime with `AliasLoader::getInstance()->alias(...)` are not
  visible to a text-based reader. The framework defaults and the literal `config/app.php`
  array are.
- The framework file is required (`composer install`). Without `vendor/` no aliases are
  written; Intelephense cannot resolve the target classes either.
- An existing `_ide_helper.php` that was not generated by this plugin is never overwritten.
  Delete it and run the command if it does not declare the aliases.
- The plugin runs where the project is. In a remote project, `Project::run_process` runs on
  the remote server; `_ide_helper.php` is written there.

## Development

```sh
cargo test                                  # parser and mock-host tests
cargo build --release --target wasm32-wasip2
cp target/wasm32-wasip2/release/openidea_plugin_laravel_facades.wasm dist/plugin.wasm
openidea-plugin check                       # validates the package
openidea-plugin link                        # loads this folder in the IDE
```

`openidea-plugin` comes from an OpenIDEA release, or from a checkout of
[`l0ng-ai/openidea`](https://github.com/l0ng-ai/openidea):
`cargo install --locked --path crates/ide-host --bin openidea-plugin`.
